ใช้งาน starter นี้อย่างไร

โฟลเดอร์นี้มีกติกา skill agent hook script แม่แบบ และ dashboard ครบแล้ว แต่ยังไม่มีเนื้อหา งานของเราคือสั่ง agent ให้หาและอ่านเอกสาร แล้วดูความรู้สะสมขึ้นใน Obsidian และ dashboard ทุกข้อย้อนตรวจได้ว่ามาจากเอกสารไหน หน้าไหน

ต้องมีอะไรติดตั้งโฟลเดอร์กติกาลำดับใช้งานจากไอเดียสู่การทดสอบskill agent hookscriptdashboardagent อื่นถ้าติด

4 · กติกาที่ agent ทุกตัวต้องทำตาม

เขียนไว้ใน AGENTS.md ส่วน CLAUDE.md ดึงเข้ามาด้วยบรรทัด @AGENTS.md แก้ได้ตามงานของคุณ

  1. raw/ ห้ามแก้ และห้าม commit PDF หรือข้อความเต็มที่มีลิขสิทธิ์
  2. ทุก claim มีที่มา: เลขหน้า หัวข้อ Item หรือ [mm:ss]
  3. แยก fact / interpretation (ผู้เขียนหรือบริษัท) / interpretation (เรา) / open question
  4. ตัวเลขมาจากเอกสารหรือสคริปต์เท่านั้น LLM ห้ามคำนวณหรือเติมจากความจำ
  5. จดสมมติฐานก่อนทดสอบ ห้ามแก้ kill criteria หลังเห็นผล ทุกการรันคือ 1 trial ห้ามลบ experiment ที่แพ้
  6. ข้อมูลใหม่ที่ขัดกับของเดิม บันทึกทั้งคู่พร้อมที่มา ห้ามลบของเก่า
  7. ตรวจ vault ด้วย scripts/wiki_lint.py ไม่ใช่ให้ AI กวาดตา

6 · จากไอเดียสู่การทดสอบ

hypothesis มี 5 สถานะ: idea → preregistered → testing → promoted หรือ rejected ไฟล์ที่ไม่รอดไม่ถูกลบ แต่ไปอยู่ใน graveyard พร้อมเหตุผล

ขั้นที่ 1 · ได้ไอเดีย

ท้าย /ingest-paper และ /ingest-source agent เสนอไอเดีย 1–3 ข้อ ข้อที่คุณเลือกจะเป็น hypotheses/H-xxx.md สถานะ idea มี checklist ขั้นต่อไป ยังทดสอบไม่ได้

ขั้นที่ 2 · จดสมมติฐานไว้ก่อนทดสอบ (pre-registration)

บอก agent ว่าจะทดสอบอะไร ใช้ข้อมูลช่วงไหน คาดว่าผลออกทางไหน แพ้เมื่อไร และใช้สคริปต์อะไร ตัวอย่าง:

จด H-001 เป็น preregistered ก่อนทดสอบ:
signal 12-7 (ผลตอบแทนสะสมเดือน t-12..t-7 ตาม Novy-Marx 2012) เทียบ baseline 12-1
universe SET100 รายชื่อปัจจุบัน (มี survivorship bias โดยตั้งใจ เขียนไว้ด้วย)
in_sample 2010-01..2019-12 · out_of_sample 2020-01..2025-12 · expected_sign positive
kill_criteria "OOS t-stat < 1.5 หรือ Sharpe < 0.3 หลังหักค่าธรรมเนียม 30 bps"
test_script scripts/backtest_momentum.py

ถ้ายังไม่รู้ว่าจะใช้สคริปต์อะไร ให้เว้น test_script ไว้ แล้ว /log-experiment จะออกแบบให้ในขั้นที่ 3

ขั้นที่ 3 · ทดสอบ

  • /log-experiment H-001 12-7 in_sample ถ้า hypothesis ยังไม่มีสคริปต์ agent จะเสนอแผน (ข้อมูล วิธีคำนวณ metric bias) ให้อนุมัติ เขียน scripts/test_<ชื่อ>.py ลอง --dry-run แล้วจดไว้ใน hypothesis ก่อน trial แรก
  • สคริปต์รัน 1 ครั้งได้ experiments/E-001.md ตัวเลขทุกตัวมาจากสคริปต์ จากนั้น reviewer ตรวจและให้ verdict
  • in-sample ได้ pass แล้วจึงรัน /log-experiment H-001 12-7 out_of_sample ได้ แล้ว agent ตัดสินตาม kill criteria และถามคุณก่อนเปลี่ยนเป็น promoted หรือ rejected
  • เปลี่ยนวิธีทดสอบหลังเห็นผลไม่ได้ (data snooping) ถ้าอยากลองแบบอื่น ให้ตั้ง hypothesis ใหม่

9 · dashboard ทำงานอย่างไร

cd dashboard
npm install     # ครั้งแรกครั้งเดียว ลง package ทั้งหมดไว้ใน dashboard/node_modules/
npm run dev     # ทุกครั้งที่จะเปิด แล้วเปิด URL ที่ขึ้นมา เช่น http://localhost:5173
npm run index   # หลัง ingest เอกสารใหม่ (เปิดอีกหน้าต่าง) แล้ว refresh เบราว์เซอร์

npm run dev และ npm run index รัน dashboard/scripts/build-index.mjs ซึ่งอ่าน frontmatter ของ papers/ sources/ articles/ hypotheses/ experiments/ .claude/skills/ และ atoms/ แล้วเขียน dashboard/public/index.json หน้าเว็บอ่านจากไฟล์นั้นอย่างเดียว ไม่แก้ไฟล์ใน vault

ตอน vault ยังว่างจะเห็นแค่การ์ดสกิล ซึ่งเป็นสภาพปกติ การ์ดอื่นขึ้นเมื่อ ingest เอกสารแล้ว

  • ด้านบน: ช่องค้นหา และแถบความคืบหน้า (อ่านไปกี่ชิ้น ไอเดียกี่ข้อ กำลังทำกี่ข้อ เสร็จกี่ข้อ)
  • chips กรองตามชนิด: Paper · เอกสาร · บทความ · Hypothesis · สกิล
  • มุมมอง 3 แบบ: การ์ด · รายการ · แผนที่ (จาก atoms/ เห็นว่า claim ไหนเชื่อม ขัด หรือนำไปสู่ hypothesis)
  • กดการ์ดแล้วรายละเอียดเลื่อนออกมาจากด้านขวา การ์ด Hypothesis แสดง checklist และผลล่าสุด
  • การ์ดสกิลมีปุ่มคัดลอกคำสั่งไปวางใน agent การแก้ทุกอย่างจึงผ่าน skill lint และ hook เสมอ

10 · ใช้กับ agent อื่น

AGENTS.md เป็นกติกาที่ agent ทุกตัวอ่าน ส่วน skill ใน repo นี้อยู่ที่ .claude/ อย่างเดียว ถ้าจะใช้กับ agent อื่น (เช่น Antigravity CLI หรือ Codex) ให้รัน python scripts/sync_skills.py จะได้ .agents/skills/ ที่มี skill ชุดเดียวกันและ reviewer ในรูป skill ห้ามแก้ไฟล์ใน .agents/ ตรงๆ ให้แก้ที่ .claude/ แล้วรันใหม่
