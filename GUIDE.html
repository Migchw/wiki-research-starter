3 · กติกาที่ agent ทุกตัวต้องทำตาม

เขียนไว้ใน AGENTS.md ส่วน CLAUDE.md ดึงเข้ามาด้วยบรรทัด @AGENTS.md แก้ได้ตามงานของคุณ

  1. raw/ ห้ามแก้ และห้าม commit PDF หรือข้อความเต็มที่มีลิขสิทธิ์
  2. ทุก claim มีที่มา: เลขหน้า หัวข้อ Item หรือ [mm:ss]
  3. แยก fact / interpretation (ผู้เขียนหรือบริษัท) / interpretation (เรา) / open question
  4. ตัวเลขมาจากเอกสารหรือสคริปต์เท่านั้น LLM ห้ามคำนวณหรือเติมจากความจำ
  5. จดสมมติฐานก่อนทดสอบ ห้ามแก้ kill criteria หลังเห็นผล ทุกการรันคือ 1 trial ห้ามลบ experiment ที่แพ้
  6. ข้อมูลใหม่ที่ขัดกับของเดิม บันทึกทั้งคู่พร้อมที่มา ห้ามลบของเก่า
  7. ตรวจ vault ด้วย scripts/wiki_lint.py ไม่ใช่ให้ AI กวาดตา

/find-paper<ชื่อ paper | DOI>

ตรวจว่า paper มีจริงก่อนเสียเวลาอ่าน เพราะ LLM แต่งชื่อ ปี และ DOI ได้

  1. ค้น Crossref แล้วเทียบกับ OpenAlex ทีละช่อง: ชื่อเรื่อง ผู้เขียน ปี วารสาร เล่ม หน้า
  2. ถ้าข้อมูลที่ได้มาผิด ใช้ค่าจากฐานข้อมูลและบอกว่าผิดตรงไหน ถ้าไม่เจอทั้งสองแหล่ง บอกว่าอาจไม่มีจริง
  3. หาฉบับที่อ่านได้ฟรี (open access, NBER, arXiv, SSRN, เว็บผู้เขียน) ตรวจขนาดไฟล์ แล้วถามคุณก่อนดาวน์โหลด
  4. ตรวจว่าไฟล์คือต้นฉบับจริง ไม่ใช่สรุปจาก AI: ชื่อเรื่องและผู้เขียนบนหน้าแรก เลขหน้า เชิงอรรถ
  5. เพิ่มแถวใน reading-list.md แล้วรายงานเป็นตาราง

/ingest-paper<citekey>

อ่าน paper ยากครั้งเดียว แล้วเก็บไว้ใช้ทุก session พร้อมเลขหน้า

  1. แปลง PDF เป็นข้อความที่มีป้าย === pdf page N === และหาว่าเลขหน้าบนกระดาษต่างจากลำดับหน้า PDF เท่าไร
  2. อ่านให้จบทั้งเล่มก่อนเขียน
  3. เขียน source note: สรุป 3 บรรทัด · claim table 8–15 ข้อ (เลขหน้า + ประเภท fact / interpretation) · วิธีการ
  4. เขียนบทความอ่านง่าย: คำถามที่ paper ตอบ → คำตอบ → วิธี → ตัวเลขสำคัญ → ข้อจำกัด
  5. ลิงก์เข้า concept และ hypothesis ที่เกี่ยวข้อง (ห้ามแตะส่วนที่จดสมมติฐานไว้)
  6. เขียน atoms/<citekey>.json แก่นของ paper สำหรับแผนที่
  7. เสนอไอเดียวิจัยต่อ 1–3 ข้อ แล้วถามว่าจะเก็บข้อไหน
  8. รัน lint และสุ่มตรวจ 3 claim กับข้อความต้นฉบับ

ได้ papers/ · articles/ · concepts/ · atoms/ · hypotheses/ (ถ้าเก็บไอเดีย) · ต่อไป การ์ด Paper และบทความใน dashboard

/find-source<ticker> | <ลิงก์ YouTube>

ไม่ต้องรู้ว่าเอกสารอยู่ไหน และรู้ว่าชิ้นไหนยังไม่ได้อ่าน

  1. ดูว่าเป็นหุ้นไทย (อยู่ใน set100.txt) หุ้น US หรือลิงก์คลิป
  2. หุ้นไทย: หาเว็บ IR ของบริษัท กวาดลิงก์ PDF (56-1, MD&A, งบ, presentation) และตรวจว่าโหลดได้
  3. หุ้น US: ดึงรายการ 10-K, 10-Q, 8-K จาก SEC EDGAR
  4. คลิป: ดึงคำบรรยายด้วย yt-dlp ถ้าไม่มีคำบรรยาย โหลดเสียงแล้วถอดในเครื่อง
  5. ส่งตารางให้เลือก ยังไม่ดาวน์โหลดจนกว่าคุณจะเลือก
  6. โหลดแถวที่เลือกไปที่ raw/sources/ ตรวจว่าเป็นบริษัทและงวดที่ถูก แล้วจดคิวใน source-list.md

/ingest-source[source-id] ไม่ใส่ = ดูคิว

เอกสารบริษัทยาวเกิน context window ต้องอ่านเฉพาะส่วนสำคัญแล้วเก็บเป็นความรู้ที่ตรวจได้

  1. ถ้าไม่ใส่ id: แสดงคิวจาก source-list.md ให้เลือก
  2. แปลงไฟล์ด้วย source_to_text.py ได้ข้อความที่มีป้ายหน้า Item หรือ [mm:ss]
  3. งบรายไตรมาสที่จะคำนวณต่อ: ตัวเลขผ่าน validate_facts.py ก่อน
  4. อ่านเฉพาะส่วนสำคัญ (56-1: ธุรกิจ ความเสี่ยง MD&A · 10-K: Item 1, 1A, 7 · 10-Q: Item 2 · คลิป: ถาม-ตอบ)
  5. เขียน source note (claim table + ที่มา · published = วันที่เผยแพร่) และอัปเดตหน้าบริษัท
  6. เขียนบทความอ่านง่ายจากต้นฉบับ
  7. เขียน atoms และเสนอไอเดียวิจัยต่อ
  8. รัน lint, grep ตัวเลข 3 ตัวให้เจอในต้นฉบับ แล้วเปลี่ยนสถานะในคิวเป็น ingested

/ask-wiki<คำถาม>

ถามจากสิ่งที่อ่านแล้ว ไม่ใช่จากความจำของโมเดล

  1. เริ่มจาก companies/ หรือ concepts/ แล้วตามลิงก์ไป sources/ และ papers/ ใช้ Grep ค้น

  4. ส่วนที่ไม่มีอยู่ใต้หัวข้อ "vault ยังไม่มี" พร้อมบอกว่าต้อง ingest อะไร
  5. ถ้าต้องคำนวณ รัน Python แล้วแสดงคำสั่ง
  6. ถามว่าจะเก็บคำตอบเป็น articles/<slug>.md ไหม

/log-experiment<H-xxx> [variant] [in_sample|out_of_sample]

รัน 1 ครั้ง = 1 trial กันการรันซ้ำจนเจอผลที่ชอบ

  6. ตัดสินตาม kill criteria และถามคุณก่อนเปลี่ยนเป็น promoted หรือ rejected

ตอน vault ยังว่างจะเห็นแค่การ์ดสกิล และแผนที่ยังไม่มีจุด เป็นสภาพปกติ

6 · จากไอเดียสู่การทดสอบ

hypothesis มี 5 สถานะ: idea → preregistered → testing → promoted หรือ rejected ไฟล์ที่ไม่รอดไม่ถูกลบ แต่ไปอยู่ใน graveyard พร้อมเหตุผล

ขั้นที่ 1 · ได้ไอเดีย

ท้าย /ingest-paper และ /ingest-source agent เสนอไอเดีย 1–3 ข้อ ข้อที่เลือกเป็น hypotheses/H-xxx.md สถานะ idea มี checklist ขั้นต่อไป ยังทดสอบไม่ได้

ขั้นที่ 2 · จดสมมติฐานไว้ก่อนทดสอบ (pre-registration)

บอก agent ว่าจะทดสอบอะไร ใช้ข้อมูลช่วงไหน คาดว่าผลออกทางไหน แพ้เมื่อไร และใช้สคริปต์อะไร ตัวอย่าง:

จด H-001 เป็น preregistered ก่อนทดสอบ:
signal 12-7 (ผลตอบแทนสะสมเดือน t-12..t-7 ตาม Novy-Marx 2012) เทียบ baseline 12-1
universe SET100 รายชื่อปัจจุบัน (มี survivorship bias โดยตั้งใจ เขียนไว้ด้วย)
in_sample 2010-01..2019-12 · out_of_sample 2020-01..2025-12 · expected_sign positive
kill_criteria "OOS t-stat < 1.5 หรือ Sharpe < 0.3 หลังหักค่าธรรมเนียม 30 bps"
test_script scripts/backtest_momentum.py

ถ้ายังไม่รู้ว่าจะใช้สคริปต์อะไร ให้เว้น test_script ไว้ แล้ว /log-experiment จะออกแบบให้ในขั้นที่ 3

ขั้นที่ 3 · ทดสอบ

  • /log-experiment H-001 12-7 in_sample ถ้ายังไม่มีสคริปต์ agent เสนอแผนให้อนุมัติ เขียน scripts/test_<ชื่อ>.py ลอง --dry-run แล้วจดไว้ใน hypothesis ก่อน trial แรก
  • สคริปต์รัน 1 ครั้งได้ experiments/E-001.md แล้ว reviewer ตรวจและให้ verdict
  • in-sample ได้ pass แล้วจึงรัน out_of_sample ได้ จากนั้น agent ตัดสินตาม kill criteria และถามก่อนเปลี่ยนสถานะ
  • เปลี่ยนวิธีทดสอบหลังเห็นผลไม่ได้ (data snooping) อยากลองแบบอื่นให้ตั้ง hypothesis ใหม่

7 · script

งานที่ต้องอ่าน ตีความ หรือเขียน ให้ agent ทำ ส่วนงานที่ต้องนับ คำนวณ ตรวจ หรือแปลงไฟล์ ให้ script ทำ เพราะได้ผลเหมือนเดิมทุกครั้งและไม่เสีย token

ไฟล์ทำอะไรรันอย่างไร

8 · ใช้กับ agent อื่น

AGENTS.md เป็นกติกาที่ agent ทุกตัวอ่าน ส่วน skill ใน repo นี้อยู่ที่ .claude/ อย่างเดียว ถ้าจะใช้กับ agent อื่น (เช่น Antigravity CLI หรือ Codex) ให้รัน python scripts/sync_skills.py จะได้ .agents/skills/ ที่มี skill ชุดเดียวกันและ reviewer ในรูป skill ห้ามแก้ไฟล์ใน .agents/ ตรงๆ ให้แก้ที่ .claude/ แล้วรันใหม่

9 · ถ้าติด

อาการทำอย่างไร
