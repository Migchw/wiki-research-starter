## 0. เตรียมต้นฉบับ
- ต้นฉบับอยู่ใน `raw/sources/<source-id>.<pdf|htm|txt|vtt>` (gitignored) ถ้าไม่มี ให้บอกผู้ใช้ว่าต้องโหลดจากไหน แล้วหยุด
  - 10-K / 10-Q: SEC EDGAR (`sec.gov/cgi-bin/browse-edgar`) · 56-1 One Report: เว็บนักลงทุนสัมพันธ์ของบริษัท หรือ SEC ไทย
  - shareholder letter (`doc_type: shareholder-letter`): เว็บ IR ของบริษัท เช่น Netflix
    `s22.q4cdn.com/959853165/files/doc_financials/<ปี>/q<n>/FINAL-Q<n>-<yy>-Shareholder-Letter.pdf` · ตารางสรุปรายไตรมาสในจดหมายผ่าน validator ตามข้อ 0.5
  - คลิป: ถ้ามีคำบรรยายใช้ไฟล์ .vtt ถ้าไม่มีให้ถอดเสียงในเครื่อง (เช่น faster-whisper) แล้วบันทึกว่าเป็น machine transcript
- แปลงเป็นข้อความ: `python scripts/source_to_text.py raw/sources/<ไฟล์>` ได้ `<source-id>.source.txt` ที่มี locator
  `=== pdf page N ===` · `=== section: Item 7 ... ===` · `[mm:ss]` และ sha256 ของต้นฉบับ
- เอกสาร PDF: ดูว่าเลขหน้าที่พิมพ์ต่างจากลำดับหน้า PDF เท่าไร แล้วใช้ **เลขหน้า PDF** ตลอดทั้ง note (เขียนไว้ในหัว note)

## 0.5 ตัวเลขงบรายไตรมาสผ่าน validator แบบ F45 ก่อน
ถ้าเป็นงบหรือ MD&A รายไตรมาสที่ตัวเลขจะถูกใช้ต่อ (เทียบข้ามงวด คำนวณอัตราส่วน) ให้ทำก่อนเขียน note:
1. `python scripts/extract_pdf.py --name <ticker>-<yyyy>-q<n> --url <url> --sha256 <hash>` → `data/filings/<name>/source.md` แยกหน้า
2. เขียน schema `facts/schemas/<name>.json` (code · period · scope · unit + identity เช่น สินทรัพย์ = หนี้สิน + ส่วนผู้ถือหุ้น · margin = กำไร / ยอดขาย)
3. สกัดตัวเลขตาม `scripts/extract_facts_prompt.md` (ชี้หน้า ห้ามคำนวณ) เป็น candidate ใน `facts/runs/`
4. `python scripts/validate_facts.py --facts <candidate> --source data/filings/<name> --schema facts/schemas/<name>.json --write facts/<name>.json ...` ต้องผ่านทุกข้อ
5. ตัวเลขใน note และบทความต้องตรงกับ fact pack · ตัวอย่าง: `facts/delta-2026-q3.json`

## 1. อ่านตามโครงของเอกสาร ไม่ต้องอ่านทุกหน้าเท่ากัน

| 10-K | Item 1 Business · Item 1A Risk Factors · Item 7 MD&A |

| transcript | คำถามของนักวิเคราะห์และคำตอบ ทีละคำถาม พร้อม `[mm:ss]` |

## 2. เขียน `sources/<source-id>.md` จาก `templates/Source.md`
- frontmatter ครบ โดยเฉพาะ `published` = วันที่เอกสารเผยแพร่ (SEC filing date · วันที่ส่ง 56-1 · วันที่ไลฟ์) ไม่ใช่วันสิ้นงวด
- สรุป 3 บรรทัด · claim table 8–15 ข้อ ข้อละหนึ่งเรื่อง ทุกแถวมีที่มา (ใช้ตรวจเท่านั้น dashboard ไม่แสดงตาราง แสดงแค่จำนวนข้อที่ตรวจแล้ว)
- ประเภท: `fact` (ตัวเลขหรือข้อเท็จจริงที่เอกสารรายงาน) · `interpretation (บริษัท)` (ผู้บริหารอธิบาย คาดการณ์ หรือให้ guidance)
  · `interpretation (เรา)` · `open question`
- ตัวเลข: คัดตามที่พิมพ์ พร้อมหน่วยและงวด ห้ามคำนวณ % การเติบโตเอง ถ้าเอกสารพิมพ์ไว้ให้คัดของเอกสาร
- transcript จากการถอดเสียงอาจฟังผิด: ตัวเลขจากคลิปต้องเทียบกับ filing หรือ shareholder letter ก่อนเป็น fact
- เขียนด้วยคำของเรา ห้ามคัดลอกย่อหน้า

- เพิ่มแถวใน "สิ่งที่รู้" เฉพาะข้อที่สำคัญ แต่ละแถวลิงก์ `[[<source-id>]]` + ที่มา

- เพิ่ม source ในรายการ "Sources"

## 4. บทความอธิบาย → `articles/<source-id>-explained.md`
source note มีไว้ตรวจ บทความมีไว้อ่าน: คนที่ไม่เคยเปิดเอกสารต้องอ่านจบแล้วรู้ว่าเอกสารพูดเรื่องอะไร และตัวเลขสำคัญควรอ่านคู่กับอะไร
- เขียนจาก `.source.txt` ส่วนที่อ่านในข้อ 1 **ไม่ใช่จาก source note** · ใช้ `templates/Article.md` · `about: ["[[<source-id>]]", "[[<TICKER>]]"]` · `basis: fulltext` · `status: draft`
- โครง: `## สรุปสั้นก่อนอ่าน` (2–3 ย่อหน้า ไม่ใช่ bullet: ตัวเลขหลัก + ประเด็นที่ต้องอ่านคู่กัน) → เอกสารนี้คืออะไร ส่วนไหนอ่านแล้วได้เรื่อง →
  หัวข้อตามลำดับที่เอกสารเขียนจริง (รายได้ · ต้นทุน · เงินสด · ความเสี่ยง ฯลฯ) → คำพูดของผู้บริหารตรวจกับ filing ได้แค่ไหน (ถ้ามี) →
  `## อ่านเอกสารนี้ยังไงให้คุ้มเวลา` (ลำดับส่วนที่ควรอ่านพร้อมเลขหน้า) → `## สิ่งที่ vault ยังไม่มี` → `## เครดิตและแหล่งที่มา`
- เล่าเป็นย่อหน้า ประโยคแรกของทุกหัวข้อคือประเด็นของหัวข้อนั้น · ทุกประโยคต้องบอกได้ว่าใครทำอะไร เพราะอะไร ผลคืออะไร ·
  ทุกหัวข้อผูกกับตัวเลข เหตุการณ์ หรือคำพูดเจาะจงพร้อมที่มา (หน้า · Item · `[mm:ss]`) ในวงเล็บ
- อธิบายศัพท์ครั้งแรกในประโยคเดียวกัน เช่น **operating margin (กำไรจากการดำเนินงานหารด้วยรายได้)** · ชื่อคนครั้งแรกเขียนไทย (อังกฤษ) ·
  ชื่อผู้บริหารเอาจาก filing ไม่ใช่จาก machine transcript · บอกงวดเป็นเดือนครั้งแรก เช่น ไตรมาส 3/2026 (ก.ค.–ก.ย. 2026) · เงินเขียน `USD 619 ล้าน` · เรียกผู้อ่านว่า "คุณ"
- ตัวเลขที่คำนวณเพิ่มให้รัน Python แล้วแสดงคำสั่งในบทความ และบอกว่าเป็นการคำนวณของเรา · คำพูดของบริษัทเขียนว่าเป็นคำพูดหรือเป้าหมาย ไม่ใช่ fact
- ห้าม: bullet ทั้งบท · "ไม่ใช่ X แต่เป็น Y" เกิน 2 ครั้ง · วลีสำเร็จรูป ("ที่แท้จริง", "ปลดล็อก", "จับตา", "อย่างมีนัยสำคัญ", "ตรงๆ") ·
  เติมข้อมูลจากความจำของโมเดล · คัดลอกย่อหน้าจากต้นฉบับ
- **ภาพประกอบ** ถ้าเอกสารมีกราฟหรือแผนภาพที่ช่วยให้เข้าใจ (เช่น slide ใน presentation) เลือก 1–3 ภาพ:
  `python scripts/crop_figure.py <pdf> <หน้า PDF> assets/<source-id>/p012-<ชื่อ>.png` (เพิ่ม `--above "<caption>"` ถ้าจะตัดเฉพาะภาพ)
  เปิดดูภาพก่อนเขียน แล้วฝัง `![[assets/<source-id>/<ไฟล์>.png]]` ตามด้วย caption ตัวเอียง: หน้า + สิ่งที่เห็นในภาพ
  · `assets/` ไม่ commit และ dashboard ซ่อนภาพที่ไม่มีไฟล์ caption จึงต้องอ่านรู้เรื่องแม้ไม่มีภาพ
  · 56-1 และ MD&A ส่วนใหญ่เป็นตาราง ไม่ต้องทำเป็นภาพ ถ้าอยากให้เห็นแนวโน้มให้วาดเองด้วย ```` ```mermaid ```` (`xychart-beta`)
  จากตัวเลขที่คัดแล้ว พร้อมหน้าที่มา ตัวอย่างใน `articles/delta-56-1-2025-explained.md`
- ลิงก์บทความจากหน้าบริษัท (หัวข้อ "Sources") และปิดท้ายบทความด้วย "เพื่อการศึกษา ไม่ใช่คำแนะนำการลงทุน"
