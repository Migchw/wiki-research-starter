# /ingest-paper

Argument: `$ARGUMENTS` · มาตรฐานตัวอย่าง: `papers/jegadeesh-titman-1993.md` คู่กับ `articles/jegadeesh-titman-1993-explained.md`

กติกาที่ใช้ตลอด: ทุกข้อเท็จจริงต้องหาเจอในต้นฉบับพร้อมเลขหน้า · เขียนด้วยคำของเรา ห้ามคัดลอกย่อหน้าหรือตาราง ·
ห้าม commit PDF หรือข้อความเต็ม · ห้ามเติมรายละเอียดจากความจำของโมเดล

## 0. เตรียมต้นฉบับ
1. ถ้า metadata ยังไม่ ✅ ใน `reading-list.md` ให้ทำ `/find-paper` ก่อน
2. หาไฟล์ใน `raw/pdf/` แล้วกำหนด **basis** (บันทึกใน `verified_against` ของ source note และ `basis` ของบทความ):
   - `fulltext` = ฉบับตีพิมพ์ เลขหน้าเป็นของวารสาร
   - `working_paper` = ฉบับ working paper (เช่น NBER) เลขหน้าเป็นของ working paper และต้องเขียนเตือนว่าตัวเลขอาจต่างจากฉบับตีพิมพ์
   - `abstract` = มีแค่ abstract เขียนเฉพาะสิ่งที่ abstract รองรับ ไม่มีเลขหน้า
3. แปลงเป็นข้อความไว้ในเครื่อง (ไม่ commit) แล้วตรวจว่าแต่ละหน้ามีเลขหน้ากำกับ ใช้ PyMuPDF (`pymupdf`) เป็นหลัก
   เพราะ pypdf อ่านฟอนต์บางแบบแล้วคำแตก (เช่น "cumula tive" ใน Daniel-Moskowitz WP):
   ```bash
   python -c "import pymupdf,sys;d=pymupdf.open(sys.argv[1]);open(sys.argv[2],'w',encoding='utf-8').write('\n'.join(f'=== pdf page {i+1} ===\n'+p.get_text() for i,p in enumerate(d)))" raw/pdf/<ไฟล์>.pdf raw/pdf/<citekey>.txt
   ```
   **เลขหน้าที่อ้างคือเลขที่พิมพ์บนหน้ากระดาษ** (เลขวารสาร หรือเลขท้ายหน้าของ WP) ไม่ใช่ลำดับหน้าของไฟล์ (`pdf page N`)
   ซึ่งมักเลื่อนเพราะปกหรือหน้าแรกไม่มีเลข เช่น DM WP: pdf page 9 = WP p. 7 ก่อนเขียน ให้เปิดดูเลขที่พิมพ์ของหน้าแรกๆ
   แล้วบันทึกส่วนต่างไว้ใต้ claim table เช่น "WP p. = pdf page − 2"
   ถ้าข้อความอ่านไม่ได้ (เช่น ไฟล์สแกนที่ OCR เสียแบบ CJL 1996 WP) ให้เรนเดอร์หน้าที่ต้องใช้เป็นภาพแล้วอ่านทีละหน้า
   และบันทึกใน source note ว่าอ่านจากภาพ
   ตารางที่แปลงจาก PDF มักเพี้ยน ให้อ้างตัวเลขจากเนื้อความเป็นหลัก และตรวจตัวเลขในตารางกับประโยครอบข้างทุกครั้ง

## 1. อ่านให้จบก่อนเขียน
อ่านทั้งไฟล์ ไม่ใช่แค่ abstract กับ conclusion จดเป็น claim ledger ระหว่างอ่าน: ข้อความสั้นๆ · หน้า · ประเภท

## 2. Source note → `papers/<citekey>.md`
ใช้ `templates/Paper.md` เติม frontmatter จาก Crossref (title, authors, year, journal, volume, issue, pages, doi, url)
พร้อม `verified_against` และ `status: ingested` (ถ้า basis เป็น `abstract` ให้คง `status: queued`)
- **สรุป 3 บรรทัด** ใส่ตัวเลขหลักพร้อมเลขหน้า
- **Claim table** 8–15 ข้อ ข้อละหนึ่งเรื่อง ใช้ตรวจเท่านั้น (dashboard ไม่แสดงตาราง แสดงแค่จำนวนข้อที่ตรวจแล้ว) ทุกแถวมีหน้า/ตาราง แยกประเภท `fact` · `interpretation (ของผู้เขียน)` · `interpretation (ของเรา)` · `open question`
- **วิธีการ** data, universe, ช่วงเวลา, วิธีสร้าง signal และพอร์ต, ค่าธรรมเนียม
- **ใช้กับงานเราอย่างไร** ลิงก์ hypothesis และ concept ที่เกี่ยวข้อง และบอกว่าวิธีของ paper ต่างจาก backtest ของเราตรงไหน
- **Open questions** สิ่งที่ต้องทดสอบกับหุ้นไทย

## 3. บทความอธิบาย → `articles/<citekey>-explained.md`
ใช้ `templates/Article.md` · `about: ["[[<citekey>]]"]` · `basis` ตามข้อ 0 · `status: draft`
- เขียนให้คนทั่วไปตามได้: โจทย์ของ paper มาจากไหน → ผู้เขียนทดสอบอะไร → วิธีอ่านตารางหลัก → ผลแต่ละส่วน →
  ผู้เขียนสรุปอะไรและยังตอบอะไรไม่ได้ → **อ่าน paper นี้ยังไงให้คุ้มเวลา** (ลำดับ section ที่ควรอ่าน) → **ต่างจากงานของเราตรงไหน** (ตาราง)
- ใส่เลขหน้าในวงเล็บทุกครั้งที่อ้างข้อเท็จจริงจาก paper
- ภาษา: เรียกผู้อ่านว่า "คุณ" · ชื่อคนครั้งแรกเขียนไทยแล้วตามด้วยอังกฤษในวงเล็บ · ชื่อผลงานเป็นตัวเอียง ·
  อธิบายศัพท์เทคนิคครั้งแรกในย่อหน้าเดียวกัน · ห้ามขึ้นทุกย่อหน้าด้วย bullet · หลีกเลี่ยงวลีสำเร็จรูป เช่น
  "ที่แท้จริง", "อย่างมีนัยสำคัญ" (ใช้ "มีนัยสำคัญทางสถิติ"), "ไม่ใช่ X แต่เป็น Y" ซ้ำหลายครั้ง
- ชื่อคนที่ paper อ้างถึงให้ตรวจกับรายการอ้างอิงท้าย paper ก่อนเขียนชื่อต้น
- งานอื่นที่ paper อ้างถึงให้เขียนว่าเราอ้างผ่าน paper นี้ ถ้าเรายังไม่ได้อ่านต้นฉบับของงานนั้น
- ถ้าจะชี้ไปผลของเรา ใช้ ```` ```ledger H-xxx ```` ห้ามพิมพ์ตัวเลข backtest
- **ภาพประกอบ** ถ้า paper มีกราฟที่ช่วยให้เข้าใจเร็วขึ้น (เช่น ผลตอบแทนสะสม) เลือก 1–3 ภาพ:
  `python scripts/crop_figure.py <pdf> <หน้า PDF> assets/<citekey>/wp-p06-figure-1.png --above "Figure 1:"`
  เปิดดูภาพก่อนเขียน แล้วฝัง `![[assets/<citekey>/<ไฟล์>.png]]` ตามด้วย caption ตัวเอียง: Figure กับหน้า + สิ่งที่เห็นในภาพ
  · `assets/` ไม่ commit (ลิขสิทธิ์) และ dashboard ซ่อนภาพที่ไม่มีไฟล์ caption จึงต้องอ่านรู้เรื่องแม้ไม่มีภาพ
  · ตารางไม่ต้องทำเป็นภาพ ถ้าอยากให้เห็นแนวโน้มให้วาดเองด้วย ```` ```mermaid ```` (`xychart-beta`) จากตัวเลขที่คัดแล้ว พร้อมหน้าที่มา
- ปิดท้ายด้วย `## เครดิตและแหล่งที่มา` (citation เต็ม + DOI + basis + วันที่ตรวจ)

## 4. ลิงก์เข้ากับส่วนอื่นของ vault
- `reading-list.md`: เปลี่ยนสถานะเป็น ✅ 📄 พร้อมลิงก์ source note
- concept ที่เกี่ยวข้อง: เพิ่มลิงก์ใต้ `## หลักฐาน (ลิงก์ paper)` ถ้ายังไม่มี concept ที่เหมาะ ให้สร้างจาก `templates/Concept.md`
- hypothesis ที่เกี่ยวข้อง: แก้ได้เฉพาะส่วน `## ทำไมถึงคิดว่าน่าจะใช้ได้ (กลไก)` หรือเพิ่มบรรทัดหมายเหตุ
  **ห้ามแตะส่วน Pre-registration และ `kill_criteria`** ถ้า paper ใหม่ทำให้อยากเปลี่ยน signal ให้เสนอเป็น hypothesis ใหม่ (`status: idea`)

## 5. ตรวจและรายงาน
1. `python scripts/wiki_lint.py` ต้อง PASS
2. `git status --short` ต้องไม่มีไฟล์ใน `raw/pdf/` หรือ `.txt` ของข้อความเต็ม
3. สุ่มตรวจตัวเอง 3 ข้อที่เฉพาะที่สุดในบทความกับข้อความต้นฉบับ (grep เลขหรือวลีในไฟล์ `.txt`)
4. รายงานผู้ใช้: basis · จำนวน claim · ไฟล์ที่สร้าง/แก้ · จุดที่ยังไม่แน่ใจหรือรอต้นฉบับ
